# UDP Source Publication

## Scope

This independently tested state model is a dependency of Android transport
integration. Its publication does not activate the remaining Runner changes.

## Input Contract

| Input | Required caller proof |
| --- | --- |
| Fresh sources | Actual concrete sources of current prepared or live socket owners |
| Retained sources | Existing authenticated active owners still available within their original lifetime |
| Protected aliases | Explicit configuration and concrete listeners; automatic cleanup must not remove them |
| Overlay prefixes | Never generate an underlay alias inside our overlay |

The model receives address values, not sockets, leases or retry tickets.
Receiving an address cannot extend any underlying owner's lifetime.

## State Rules

| Case | Result |
| --- | --- |
| Fresh, eligible source | Add its concrete alias once |
| Existing retained source | Keep an already-generated alias; never create a new alias from retention evidence |
| Missing source | Remove only aliases previously generated by this model |
| Explicit override | Preserve unrelated and protected aliases |
| Unchanged snapshot | No metadata change or capability-delivery restart |
| Overlay, unspecified, multicast or zero port | Do not generate an alias |
| IPv6 link-local | Do not export a device-local interface scope as a portable endpoint |
| Resource bound | At most 32 generated aliases, shared by fresh and retained sources |

Input ordering is normalized. At capacity, retain necessary fallback aliases
rather than evicting them to publish a new candidate.

## Integration Obligations

1. Select and retain the actual source before signing Hello or Accept.
2. Queue changed metadata through the existing capability-delivery owner.
3. Require its matching acknowledgement before signing either transcript.
4. Adopt the exact prepared owner and require authenticated path validation.
5. Reconcile cancellation, expiry, source loss and physical-network changes.

A native connection's external hint is not raw-UDP NAT mapping proof.
Network-scoped DNS, transport activation and device validation remain separate.

## Local Runtime Reconciliation

The working integration combines UDP and owned-QUIC aliases through one
reconciler. This activation is not published or verified on Android hardware.

| Claim | Lifetime and withdrawal |
| --- | --- |
| Explicit configuration / concrete listener | Protected startup template; automatic cleanup cannot remove it |
| Native control connection | Exact adopted registration and connection ID; close, revocation or definitive Android source loss removes that claim |
| Prepared UDP | Current preparation or active source; exact-owner adoption and metadata ACK requirements remain unchanged |
| Confirmed external address | Current swarm observation; duplicate observations may support the same alias |
| Retained payload owner | May retain an existing generated alias, never introduce a new one |
| Outgoing-only QUIC socket | Its ephemeral port is not an advertised server; an active session may retain the original listener alias |

Ownership is reconciled before publishing the effective alias lists. Removing
one claim cannot remove an alias supported by another claim. A shared port is
not evidence that another source is stale.

| Boundary | Local rule |
| --- | --- |
| Metadata delivery | Broadcast effective list/flag changes only; unchanged owner sets preserve existing ACK state |
| Bounds | At most 64 native claims and 32 generated aliases per UDP/QUIC list, shared by fresh and retained aliases |
| Listener loss | Withdraw automatic aliases; explicit inactive configuration remains intact |
| Preference change | Preserve available fallback ownership; do not treat revision churn as definitive loss |
| Linux source audit | Keep live ownership until asynchronous audit/connection retirement supplies the loss verdict |
| RX-only drain | Does not authorize an advertisement or extend the original receive lifetime |

Host ownership models and real scoped QUIC tests are tracked separately from
Android kernel/netd and device handoff acceptance in the fixed ledger.

## Evidence

Six focused model tests cover idempotence, concurrent sources, withdrawals,
explicit overrides, overlay/address filtering and shared fresh/retained bounds.
The extracted component passes those tests, Android arm64 release compilation
and format checks independently of the larger working change.
Integration and device results are tracked in the
[acceptance ledger](physical-network-acceptance.md).
